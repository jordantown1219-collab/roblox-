# Storefront door component

`BuildingInteractions.door(config)` returns an unparented original door component centered on its closed leaf. Supply it to `BuildingTemplates.storefront(config, component)`, then destroy the original component when no longer needed. The storefront clones it. `apertureWidth` and `apertureHeight` must match the storefront door dimensions; defaults6×9studs. Supported widths5..8 and heights8..11. Leaf margins are.3stud on each side and.15above/below. There is no separate collision frame intruding into the shell aperture.

The component uses the existing InteractionRegistry contract unchanged: Moving Model, Leaf, MotionPivot, Control with ProximityPrompt, Hinge/Y motion, Range9 and Duration.8. Travel defaults90degrees and is restricted75..90; a95degree swing would turn the wide leaf back into the storefront jamb. All parts are anchored, touch events disabled; only the leaf collides. Handle is noncolliding. Model pivot is the closed leaf center; the hinge is its left edge. Control sits in the left jamb gap, outside the door sweep, with a ray path through the aperture from either side. No per-instance Scripts or new remotes are created. Existing central server validation remains responsible for alive/team/match/distance/line-of-sight/obstruction and cooldown checks. LobbyInteraction is deliberately unset.

Config also accepts duration.25..2seconds, travel75..90degrees, colorColor3. The model is taggedSSInteractable and uses Atomic streaming. Build the full template tree, parent it into the intended registry root, then call InteractionRegistry.start(root). The existing registry scans initial tags and listens for newly added tags; it does not observe arbitrary descendant insertion. Do not assume inserting an already-tagged clone into a running root registers it. This component currently targets the authored/bake path. The caller owns registry lifecycle and component destruction. The factory alone does not start interactions.

`tests/STUDIO_BUILDING_INTERACTION_CHECK.lua` requires BuildingInteractions and BuildingTemplates in ServerScriptService. It constructs three shell/door sizes at isolated height, checks component contracts, tests25motion samples against actual shell collision boxes, checks control exclusion from the sweep, restores the exact closed pose and verifies invalid inputs. Test fixtures clean up on failures. This validates geometry only. Actual prompt activation, opening from both sides, moving-player obstruction, team/size rules, touch/controller use and multiplayer replication require Lead acceptance tests before claiming a finished functional building. A sliding window is deferred; static storefront glazing remains unchanged.
