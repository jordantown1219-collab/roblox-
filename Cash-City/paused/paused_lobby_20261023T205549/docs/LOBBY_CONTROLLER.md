# Pure lobby queue and ballot controller

LobbyController.lua has no Roblox dependencies, clocks, remotes, side effects or per-player scripts. The Lead adapter supplies authenticated user IDs, current server time and real supported map/mode catalog entries. This module does not teleport, load maps, assign Roblox Teams, launch matches or publish anything.

API: `Controller.new(config)`; `join(userId,mode,size,now)`; `leave(userId)`; `voteStart(userId,epoch,now)`; `voteMap(userId,mapId,epoch,now)`; `tick(now)`; `snapshot(userId,now)`. Mutations return booleans except tick, which returns one completed selection or nil. IDs are finite nonzero integers, including negative Studio test IDs. Time must be finite/nonnegative. Snapshot falls back to time0 for an invalid read time; it never advances the state. Existing members must leave before changing their queue choice. Practice remains outside this module.

Config contains teamSizes3/4/5, waitSeconds90, voteSeconds12 and ordered maps/modes catalogs. Every item needs a unique safe string ID; only `available=true` entries are selectable. At least one available map and mode are required; there is no fake fallback. Map labels/size/recommendedTeamSize are retained for presentation but recommendations do not exclude otherwise available maps. The adapter must only mark maps available when their runtime loading contract is real. Catalog/config and returned snapshots are copied, preventing normal caller edits to a returned table from mutating internal state.

Tick checks full6/8/10player rosters before waited smaller starts. Queue choices are checked in ascending requested size, then mode ID; participants are sorted by numeric ID and only the first required count is reserved. Smaller starts need at least two players,90seconds elapsed since the earliest remaining member of that group joined, and a strict majority of that CURRENT group. Repeated start votes count once. Odd smaller groups reserve the lowest even count; the highest unmatched ID remains queued. No bots are added. Start ballots may be cast only after the wait deadline, not precollected. Removing a queued voter removes their ballot automatically.

A single MapVote phase reserves its participants for12seconds. Other users can still join queues, but the controller cannot start another ballot until this one resolves/cancels. Nonparticipants, unavailable maps, old epochs, times before the ballot start and times at/after its deadline are rejected. A player's new map vote replaces their previous vote. Highest count wins; equal counts (including no votes) choose the lexicographically smallest available ID deterministically. There is no invented default map.

If a reserved participant leaves, their vote is removed and the highest remaining participant returns to their original queue whenever needed to keep the reservation even. Their map/start ballots are cleared. Fewer than two reserved participants cancels the vote, restores Queue and increments epoch. Otherwise the existing ballot deadline remains, with the reduced balanced roster. A completed selection is returned only once: `{players={IDs},mode,mapId,teamSize=<actual>,requestedTeamSize=<queue choice>}`. Only those selected IDs are consumed; unselected users retain their original queues. The adapter assigns actual team membership and must preserve existing individual shrinking/whole-team extraction rules.

Snapshot exposes phase, epoch, deadline, unreserved queues keyed by requested size, ready membership, the requesting player's selected teamSize/mode, canStartSmall, startVotes/startNeeded, available-map vote counts, full presentation catalogs and the player's votedMap. During MapVote, teamSize remains the queue choice; actual reduced team size is in the final selection. Queue counts aggregate available modes; start ballots themselves are grouped by both mode and size. Missing optional fields are nil. Epoch changes when entering/leaving a ballot, preventing stale phase votes.

Lead integration must call tick only when the global game is in its Lobby state; during an active match, queues may accept nonmembers but no tick should launch a competing round. Only authenticated server callbacks supply caller IDs and trusted server time; never accept an arbitrary userId/time payload from a client. Current permission/downed/match checks remain in the existing adapter. Multiplayer membership changes must call leave. This is logic validation, not proof of remotes/UI/network behavior.

TDD evidence: focused tests first failed because no controller existed, then six Lupa test cases passed after implementation. Coverage includes full sorted rosters at all sizes,90/12second boundaries, strict majority, unmatched-player retention, replacing ballots, stale/nonmember/unavailable rejection, deterministic ties, leave/rebalance/cancel, negative Studio IDs, exactly-once selection and snapshot/config isolation. Run `python -m unittest discover -s tests -p test_lobby_controller.py -v`. Native Studio, integration, multiplayer/device and visual acceptance remain Lead work.
